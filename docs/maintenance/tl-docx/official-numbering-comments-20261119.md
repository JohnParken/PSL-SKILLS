# TL-DOCX：公文、原生编号和批注验收

工作树基于 main `78d56cc`；对照 docx 的 generation-blocks、p1-layout、comments-management 与实现。未改变 docx 业务代码、生产依赖或包边界，不更新 dist 发布包。

| 需求 | 原先差距与验证 |
| --- | --- |
| 公文落款与横向附件 | 原本可手工写普通段落和展开的分节设置。TL 新增声明式落款，检查两段右对齐、首行零缩进、署名随日期而非日期随附件；新增嵌套页面几何及分节类型别名，保留旧写法并拒绝矛盾设置。测试从生成的 XML 独立核对纵横纵三节和继承边距。 |
| 原生编号 | docx 四级标题定义不注入普通列表悬挂缩进。TL 校正标题与列表区别，支持具名列表首块起号、跨段续号，中文常用序号生成后正确读回；超范围显式诊断。混合安装用例另发现已有段落属性中追加 numPr 可能破坏顺序，修复生成而非降低静态校验。 |
| 批注 | 保留简单、明确锚点及原文保护机制。TL 针对已有经典部件安全新增根批注（不升级）；现代完整四部件可解决与重开根线程。专项回归检查非目标部件字节、回复与锚点不变，以及原文失配/不支持操作拒绝。 |

**实际验证：** macOS arm64，仓库项目环境 Python 3.12.12 / python-docx 1.2.0 / lxml 6.0.4 / Expat 2.6.3。默认 python3 为 3.9.6 且无 docx，不满足条件，两者不混记。

- TL 全量源码测试：397 项通过。通用打包安全 11 项通过。12 个独立只读安装包合计 22 项通过，含混合公文创建、编号读回和批注状态往返。包装门禁禁止访问源码仓库，用仓库外的临时离线锁定依赖环境；未放松隔离。
- TL 严格结构、项目文档检查、选择指纹 6 项、既有计划加载快照一致性和 diff 空白检查通过。快照不是宿主实测。无新运行模块，runtime manifest 不变。
- Pylint 不在项目环境或可用离线缓存，未执行。样本为合成；未验 Word/WPS 视觉、实际签章/版记、Linux/Windows 部署或 DeepAgents 真实运行。只读标签重建非版式引擎；旧缓存须用原版本释放，旧游标重新开始。
