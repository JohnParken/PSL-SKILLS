## 根因与复现

调用链为 `read_docx.main` → `read_docx_report` → `docx_read_pages.report_page`。报告分页不是解压目录，其唯一跨调用中间文件是任务根目录的独占解析缓存。

旧 CLI 只追踪 `page_cache=stored` 的首次游标。合成文档首次分页后，对 `page_cache=reused` 的续页注入输出失败，退出 2 后仍遗留 1 个本轮缓存。旧实现还在真实分页预算失败时保留已核实缓存，文本 stdout 没有在清理异常窗口内显式刷新，未捕获输出中断或非预期序列化异常。

## 修复与保护边界

- 首次及复用页均追踪未交接游标，输出或序列化失败时按原游标验证后释放；文本与二进制 stdout 在交接前刷新。
- 已核实缓存的分页失败及可捕获中断立即释放；正常非末页保留有效缓存供续读，末页自动释放。原游标在缓存缺失时仍可从未变化的输入重建。
- 不扫描历史文件；输入、用户保存的 `-o` 结果、其他游标及未知文件不参与清理。身份/内容变化、链接及权限异常继续拒删并报告清理未完成。
- 源/选项尚未通过校验时不认领缓存；提前结束可用原游标 `--release-cursor`。SIGKILL、宿主崩溃或停止调用没有可运行的收尾保证，不声称能自动清理全部历史残留。
- 不在归档目录创建缓存，不改变归档、创建/编辑 runner、公用生命周期实现或分发边界。
