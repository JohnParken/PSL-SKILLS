# 归档 v2 改造验收（2026-11-12）

## 已实施

- 统一为 `scripts/archive_delivery.py` / `archive_delivery()`；删除旧归档入口与覆盖参数。
- 每次调用重新读取宿主当前 questionId；缺失或无效明确失败，不沿用历史回执目的地。
- 最终交付物显式清单、原件保护、同名异内容拒绝、同内容核验后幂等成功。
- 批次状态 success / partial / failed / not_required，与各文件 copied / already_archived / failed 分离。
- DOCX 恢复不重复生成，按本次配置重新归档；WPS/XLSX/PPTX 创建与跨表工作流适配统一回执。
- ET/OFD 仅对用户明确指定的最终交付文件调用归档；读取中间 JSON 不自动归档。
- 各技能随包独立携带运行时；来源哈希、分发白名单与只读独立安装测试同步。
- 所有暂存及自检探针在任务根目录平铺；归档目录及子目录不放临时校验文件。

- 沿用任务根暂存、独占硬链接发布、发布后最终摘要复核；没有采用归档目录暂存或新云上传协议。失败目标可能已被云机制观察，不能承诺整批事务或上传已验证。
- 已有路径保护不能被解释为针对恶意并发目录置换的完整操作系统级隔离。

## 归档遗漏后续修复（2026-11-12 UTC）

本节针对先前覆盖审查发现的边界增量修复，不覆盖或抹除本页前一轮验收事实。

- WPS 正式交付未就绪（业务、发布或内部清理失败）统一返回 failed、明确阻塞原因及请求文件清单，不再把它报告为 not_required；主文件保留，验证恢复后仅重试归档。
- 跨表明确 XLSX 与审计 JSON 两件最终交付清单。两件均准备及回读验证好才归档；准备阶段部分失败保留文件并标记 not_ready，不自动作为单独最终交付。逐项归档异常与部分成功如实汇总，完整与有界回执都保留整批状态。
- ET 新增 --output 文件名 --delivery，只有显式最终 JSON 才自动归档，内部读取结果不归档；以流式字节、摘要和身份核验防止交付前后文件变化，失败保留主文件与可能已存在的副本证据。
- DOCX 读取 --delivery 与低层内部产物边界明确，补充缺 ID、幂等和当前 ID 重试测试；XLSX 协议 publish 明示待收尾，不能把写入等同归档。OFD 仍不提供写入，宿主保存用户最终提取结果后显式交接。
- README 给出逐入口覆盖矩阵；六个技能同步说明及版本。description 能力选择边界核对后保持不变。人工复核现有选路场景，更新当前指纹和静态读取计划，不声称模型选路或 token 测量。
