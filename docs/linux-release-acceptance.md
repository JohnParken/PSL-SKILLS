# 三个最终包的云端 Linux 上线验收

## 当前状态与适用范围

本清单是待执行方案，不是 Linux 通过报告。本次会话可用执行器为 Darwin arm64；未发现 Docker、Podman、Lima、Colima 或云端命令工具，尚未提供 SSH 目标和容器入口。仅发现 ssh 客户端不能证明存在已授权的远端环境。待提供连接方式、容器名和允许写入的隔离测试目录后执行。

已有 macOS 回归不能替代 Linux；既有 os._exit 故障注入也不能替代真实 SIGKILL、整容器强停及宿主恢复验收。不要将任何未执行项填写为通过。本轮未修改三个分发包。

## 环境与包检查

1. 记录云端实例/容器标识、镜像摘要、内核、架构、Python 和 Expat 版本、UID，以及任务目录的挂载方式。不要记录完整环境变量或凭据。
2. 用正常生产运行用户验收，不以 root 权限掩盖权限错误。安装目录只读，任务目录可写；如生产环境 `/tmp` 只读，验收环境保持一致。不要改 TMPDIR 来掩盖业务脚本越界写入。
3. 上传后核对以上 SHA-256，再检查 ZIP CRC、成员路径和完整成员集合；拒绝越界成员、符号链接或多余文件。解压到独占安装目录，执行前后比较完整文件清单与哈希。
4. 从真实读取的 SKILL.md 路径定位各 Skill，分别完成其环境自检。DOCX 正常 create 内置自检；XLSX 按主入口 check。缺少必需能力就停止，不降级文件安全操作。
5. 每个业务案例独立任务目录。预置合成的原件和历史交付物，记录路径及哈希；业务中间文件只平铺于该案例的 `./`。验收报告存于独立证据目录，由测试控制者管理，不混入业务任务目录。

以下是维护测试命令模板。`<python>`、`<installed>`、`<maintenance>` 和 `<evidence>` 均须替换为宿主确认的真实路径；不要把占位符原样执行。`<maintenance>` 是只包含所需维护资源的目录，`<installed>` 含三个已解包的 Skill。工作目录使用隔离的维护验收目录，不能切到 Skill 安装目录生成业务文件。

```console
"<python>" -I -S -B "<maintenance>/skills/skill-development-standards/scripts/check_skill.py" "<installed>/bank-writing" "<installed>/docx" "<installed>/xlsx" --strict
TEMPLATE_SKILLS_ROOT="<installed>" "<python>" -I -S -B -m unittest discover -s "<maintenance>/tests" -p test_complex_json_templates.py -v
"<python>" -I -S -B -m unittest discover -s "<installed>/docx/scripts" -p 'test_*.py' -v
"<python>" -I -S -B -m unittest discover -s "<installed>/xlsx/scripts" -p 'test_*.py' -v
```

上述现有测试使用 tempfile 建立维护测试沙箱。若系统临时目录不可写，应另在明确授权的维护验收目录配置其测试用临时根，并记录这一条件；这不能证明生产业务未访问 `/tmp`。还须在生产挂载限制下独立运行下述真实业务案例。逐条保存 stdout、stderr、真实退出码；测试为零项、跳过或未启动均不得算通过。

## 成功与失败案例

| 案例 | 操作 | 独立验收条件 |
|---|---|---|
| 写作成功 | 用虚构材料生成一份纯文本总结，不请求导出 | 文本符合材料；没有 execute 调用或本地中间稿；原件/历史交付物未变 |
| 写作材料读取失败 | 提供宿主不可读取的素材引用 | 如实报告缺口，不虚构读取结果；不创建临时文件 |
| 写作交接 | 对已确认正文请求 DOCX | 交接完整正文，读取真实 DOCX 入口，执行 DOCX 同样的成功/失败验收 |
| DOCX/XLSX 成功 | 执行各自 complex-json.md 的实际模板，包含中文、引号、反斜杠和字面量 `$()` | 正文/单元格值独立核对；包可读；退出与摘要一致；临时项和清单消失；原件及历史交付物哈希不变 |
| 业务失败 | DOCX 使用不支持的 block type；XLSX 使用无效 spec | 非零退出；业务失败不变成成功；本轮辅助文件和清单清完；原件未变 |
| 序列化失败 | Python 对象包含 NaN，保留 allow_nan=False | runner 未启动；退出非零；无新增业务临时文件；不得打印完整敏感数据 |
| Python 语法错误 | 在调用源码引入明确语法错误 | 不启动 runner；若源码落盘，外层按创建前的清单完成收尾 |
| 归档失败 | 使用验收环境支持的失败配置或只读归档目标 | 保留已验收主文件，归档如实失败；本轮中间文件照常清理，不重新生成 |
| 删除失败 | 在独立测试夹具中阻断一个已登记项的删除 | cleanup_incomplete，不声称完成；解除阻碍后按原清单恢复，最终无临时残留 |

逐案例保存运行前后目录差异，不能只检查某一种文件后缀或 cleanup_complete。正常收尾后，目录只能含基线受保护文件和已确认交付物；不得通过测试脚本预先删除残留制造通过结果。

## 强制中断：必须由外部控制者验收

被 SIGKILL 的进程不能自行运行 finally；“终止后留待恢复”是中间状态，不能作为清理成功。验收目标是外部控制者确认进程退出后，安全完成恢复且不损坏交付物。若产品要求强杀也自动清完，必须验证宿主的独立恢复控制者；只有 Skill 内部逻辑不足以证明这一能力。

每个案例使用本次创建的独占进程组或专用测试容器，记录其身份；禁止使用 pkill、模糊进程名或停止共享生产容器。以握手/事件确认中断阶段，不能凭固定 sleep 猜测。可以在独立测试控制器中做暂停注入，但不能改写安装包，并明确区分注入与无修改运行的证据。

| 中断位置 | 中断方式 | 验收重点 |
|---|---|---|
| 清单建立后、worker 仍运行 | 分别仅杀父进程、仅杀 worker、杀本次整个进程组；分别 SIGTERM/SIGKILL | 活跃子进程未退出前不清理；记录真实状态，不伪造正常退出码；确认全部退出后恢复 |
| 生成暂存或归档复制期间 | SIGKILL 本次进程组 | 核对内部暂存是否可追溯；未登记/归属不明残留要报告，不能用递归删除掩盖缺口 |
| 主文件已验收、封存前 | SIGKILL | 已发布文件必须保留；缺少可信回执时不得冒称完成或重跑覆盖 |
| 封存后、清理开始前 | SIGKILL | 用原清单恢复，不重新生成；主文件哈希不变，清单最终删除 |
| 已删除部分临时项、尚未删除清单 | SIGKILL | 恢复将已不存在项视为已消失，不重建输入，不扩大删除范围 |
| 容器整体停止/宿主重启 | 仅对专用验收实例强停后启动 | 验证任务清单和身份信息是否持久化；恢复控制者是否会执行；不得仅以容器磁盘消失认定交付物保护通过 |

DOCX 已封存或已完成交付且证据齐全时，从原任务目录调用 `run_docx_task.py resume 原清单文件名`；它不是所有生成中断的通用恢复器。生成未完成、清单损坏或回执不可信时，按返回状态核实，禁止强行成功封存。

XLSX 没有通用 runner resume 命令。确认全部进程退出及原清单归属后，依据实际状态用 xlsx_lifecycle.py seal/clean；已最终封存的清单仅 clean，失败任务使用 failed，不能用 retry/retain 保留中间项。不得重采样变化文件指纹来绕过保护。

保留或身份检查拒绝说明保护机制起效，但“全部中间文件清理”的验收仍为未通过/待恢复。记录具体残留、原因、恢复负责人和再次核验结果，不删除未知文件。写作本身无本地生成流程；对话中断及已交接 DOCX 的取消/恢复需由真实宿主分别验收。

## 无法从本地证明的宿主集成项

| 项目 | 具体操作 | 通过标准/所需证据 |
|---|---|---|
| 空参数与重复 call_id | 在测试宿主提交一次缺 command 的调用，再一次合法调用；重放同一失败 call_id | 参数错误标记未启动，无虚构退出码；一次合法调用只执行一次；记录调度次数及调用关联，不重复生成 |
| 双通道与退出码 | 运行测试探针，stdout 输出一段合成 JSON，stderr 输出不同标记，分别返回 0/1/2/3 | 执行器载荷和模型可见结果均保留两个通道与真实退出码；非零退出不吞掉 JSON |
| 超时/信号 | 对独占探针触发宿主超时及强杀 | 明确超时或 signaled，不填0；记录取消是否覆盖子进程、何时退出、何时允许清理 |
| 结果截断 | 输出超过宿主阈值的纯合成结果 | 标注通道、截断状态与原始长度（可知时）；模型不解析截断 JSON 为完整结果 |
| 大结果隔离 | 让宿主真实产生 /large_tool_results/ 引用，通过 read_file 按真实 schema 分段读取 | 分段拼接后与原始合成结果校验和一致；模型不使用 execute/Python/cat 读取该路径；read_file 不可用时明确停止依赖操作 |
| 路径与只读安装 | 从与安装目录不同的任务根调用模板，并在只读 /tmp 条件下执行 | 输入、输出、临时项均遵循实际任务根；没有切换到安装目录或绕过挂载；安装哈希不变 |
| 脱敏 | 用可识别的合成密钥、配置值与内部路径触发错误 | 用户最终回复及可见日志无合成敏感值；机器通道按既定字段契约保留必要信息，不原样转贴 |
| 云空间和下载 | 分别模拟完整归档、失败、跳过和部分成功 | 话术与实际状态对应；链接可访问且内容哈希正确；失败不虚构成功归档或下载能力 |
| 模型路由 | 分别请求纯文本、复杂 DOCX、复杂 XLSX，再提供缺失路径和语法错误 | 写作不擅自生成；复杂JSON使用Python序列化；路径来自真实入口；错误不原样重复；所有新增中间项有收尾 |
| 自动中断恢复 | 在上述真实强杀案例后不手工删除文件，观察宿主恢复控制者 | 能关联原任务、确认进程已退出、完成安全收尾并报告；没有恢复控制者则明确不通过自动恢复验收 |

## 证据记录与放行

每条记录至少包含：包哈希、平台/镜像、案例编号、合成输入、独立预期、实际命令及cwd、信号目标身份、阶段证据、stdout/stderr/退出或中断状态、执行器载荷、模型收到的结果、运行前后文件清单和哈希、残留、恢复动作及最终结论。敏感数据只用合成值；证据文件是显式验收交付物，不是业务目录残留。

成功/普通失败清理、输入与历史交付物保护、包身份检查必须全部通过。若上线承诺包含强杀后的自动完整清理，则该项未验证或只报告保守残留时不得签署该承诺。未提供 Linux 入口前，全部 Linux 案例保持“未执行”，不沿用本机通过状态。

Main-agent work：环境可用性检查、既有中断测试证据复核、验收方案与放行条件。
Subagent execution record：未调用子代理。
