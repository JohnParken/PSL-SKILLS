# 文本到DOCX的授权交接

路径占位符说明：`<skill-root>` 是 bank-writing Skill 根目录的文档占位符，不是实际目录或 Shell 变量。取得宿主本次实际读取 bank-writing 主入口 `SKILL.md` 的真实 `file_path`，若为相对路径，先按该次读取时宿主已确认的基准目录解析为绝对路径，再去掉末尾文件名；所得目录才是 `<skill-root>`，不是当前参考文档所在目录。读取资源或执行命令前，将路径中的 `<skill-root>` 整体替换为该真实目录，保留其后的资源路径；命令中将替换后的完整路径作为一个参数正确引用，嵌入 execute 字符串时按其语法转义。不要将占位符原样交给文件工具或执行器，不按当前工作目录、其他会话路径、环境变量或宿主掩码猜测。无法取得主入口的真实读取路径时，停止依赖操作并报告无法定位。

仅在已要求DOCX、交接内容有歧义或导出故障时读本页；普通文本任务不加载，不在写作阶段调用docx脚本。

## 六、DOCX 导出交接

- 默认交付本次写作或审校文本，不在每次回复后重复询问导出。完整成稿适合文件交付且用户尚未表达交付偏好时，可在正文外简短提示 DOCX 导出能力；局部润色、提纲、摘要及明确只要文本时省略。提示不属于正文，不等待回答才交付内容。
- 只有用户确认导出，或原始请求已明确要求 DOCX，才交给本项目 `docx` Skill；已有授权时不重复询问是否导出，也不要求再次确认同一版正文。多版正文或待核事项导致导出内容不明确时，只澄清具体内容。
- 交接用户确认的最终正文及已有格式要求；若原请求已授权起草并导出，则交接按该请求完成的最终正文。排除导出提示、过程说明和用户未要求纳入的审校意见，不擅自重写事实或悄悄删除待核信息。
- 由宿主定位并读取本项目 `docx` 的真实 `SKILL.md`。仓库内入口为 `skills/docx/SKILL.md`，此路径相对于已确认的仓库根目录；独立安装时不假定相邻目录。后续环境自检、输入组织、格式选择、生成和验收遵循该技能当前说明，写作阶段不提前执行其自检。
- `docx` 不可用或其自检、生成、验收失败时，保留已交付文本并如实说明受阻；本技能不自行生成文件、不安装依赖或改用其他格式。只有生成及验收成功并核实实际文件后，才提供真实文件链接并说明已生成。纯文本或仅 stdout 不归档；文件交接继承提供方已验证的归档状态与用户提示，成功即提示去云空间查看，非成功如实报告，不虚构文件链接或暴露内部归档信息。

生成或编辑失败同样立即清理本轮临时文件和清单，不因可能重试而保留；需要重试时从原始输入重新创建独占任务。删除受阻、锁仍被占用或归属无法确认时报告cleanup_incomplete，处理阻碍后继续清理，不能宣称已完成。 交接DOCX时同时遵守此失败清理要求；已交付文本和用户原始材料不删除。

若`read_file`不可用或读取失败，报告具体缺口并停止依赖该结果的操作；不得改用execute、Python或Shell读取`/large_tool_results/`，也不得猜测替代路径。工具参数遵循实际schema，不虚构参数名。

## 导出规格的JSON选择

简单JSON（短文本、少量字段、浅层结构）可直接写；复杂JSON（长正文、多层对象或数组、表格批量数据、大量引号或反斜杠）必须用Python构造dict/list，再用json.dumps(..., ensure_ascii=False, allow_nan=False)序列化，不手工拼接JSON。Python语法与业务字段仍需核对，序列化成功不等于业务验收通过。 本技能仍直接交付文本，不为写作生成JSON或Python文件。用户要求DOCX时，交接已确认正文、数据与缺口；读取已定位docx主入口后使用其复杂JSON调用模板。由docx导出阶段构造和序列化数据，复用原runner及成功/失败清理；不猜相邻技能路径，不在写作阶段执行生成脚本。
