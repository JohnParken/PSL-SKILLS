# CFB/MS-DOC 二进制正文读取

## 入口与结果

先完成 [执行环境约束与首步自检](../SKILL.md#执行环境约束与首步自检)。从实际读取 `SKILL.md` 的路径确定 `<skill_dir>`，替换为真实目录，始终在已确认的任务工作目录运行：

```console
python -I -S -B "<skill_dir>/scripts/read_docx.py" ./input.wps -o ./body.txt
```

同一入口识别 OOXML 或 CFB 文件。CFB 使用内部模块 `<skill_dir>/scripts/office/binary_doc.py`，不安装依赖、不启动办公软件、不访问网络。保留输入和失败时的已有输出；输出只含正文文本，不含诊断信息。

二进制分支只输出 Main Document 的 CP 区间 `[0, ccpText)`，不输出页眉页脚、脚注、尾注、批注或文本框故事。保留正文末尾段落，CR 和软换行转为 LF，单元格/行标记 `0x07` 转为制表符，分页标记保留为 form feed；不重建表格行列、列表编号或页面布局。

正文按文本片段表的逻辑顺序读取，支持多片段和跨片段 UTF-16 代理对。单字节文本按 MS-DOC FcCompressed 的 24 项映射解码，其余字节映射同值 Unicode；不能整体按 CP1252、GBK 或本地编码猜测。

默认返回存储的正文字符；不解释修订、隐藏、字符或段落格式属性，可能包含删除/隐藏文字。显式 `--revisions all` 表示相同的未筛选正文；显式 `accepted`、`original`、`--include-related` 和 JSON 输出均报错。不得将其称为可见页面文字、净稿或完整文档内容。

## 支持的容器和版本

- CFB v3（512 字节扇区）和 v4（4096 字节扇区），次版本 0x003E，小端序、64 字节 mini sector、4096 字节 mini stream cutoff。
- 普通 FAT、MiniFAT、根 mini stream 和嵌套存储目录；只从根目录选择 `WordDocument` 与 FIB 指定的 `0Table`/`1Table`。
- FAT 仅使用头部最多 109 项 DIFAT；需要额外 DIFAT 扇区的文件明确拒绝。
- 有效 FIB 版本与字段数量必须匹配：

| 有效 nFib | cbRgFcLcb | cswNew |
|---|---|---|
| 0x00C1 | 93 | 0 |
| 0x00D9 | 108 | 2 |
| 0x0101 | 136 | 2 |
| 0x010C | 164 | 2 |
| 0x0112 | 183 | 5 |

存在 `nFibNew` 时按其确定有效版本；同时检查基础版本属于已支持集合。CLX 支持有界跳过 Prc 属性记录及读取唯一末尾 Pcdt。只检查读取所需结构，不解析或验证全部格式属性。

## 明确拒绝和资源限制

- 未识别的容器、未知 CFB/FIB 版本、字段数量不符、缺少必需流、加密/混淆标记、非零加密键字段及已识别的加密包装流。
- 模板、AutoText 文档、无正文、非单调或不匹配的 CP、超出 `cbMac` 的文本、截断或非法 UTF-16、缺少末尾段落标记。
- 正文中的字段控制符、嵌入对象标记及除 TAB/CR/软换行/分页/单元格标记之外的低位控制字符。只支持普通正文子集；遇到这些结构停止，不偷偷删掉控制符继续输出。
- CFB 文件和累计声明流大小均不超过 32 MiB；目录最多 4096 槽，存储嵌套最多 64 层，文本最多 100000 个片段、8388608 个总 UTF-16 码元（含其他故事）。CLX 最多 4 MiB、其中 Prc 最多 4096 条。超限报错而非截断。
- 拒绝环、扇区重叠、链长不符、越界索引、目录重复引用、同目录重名和不可达的有效目录项。输入在操作期间须保持稳定；不提供对恶意并发改写的进程隔离。

本实现不是通用 OLE、Microsoft Works 或金山私有二进制格式解析器，也不是完整 MS-DOC 校验器。安全检查与文本测试不能证明真实 WPS/Word 可打开；真实导出样本应独立验证。

## 实现依据

实现依据微软公开规范中的 MS-CFB 容器结构，以及 MS-DOC 的 Fib、FibBase、FibRgLw97、Clx、PlcPcd、FcCompressed 和 Retrieving Text 条目。运行时不下载规范。维护时须区分规范语义与本实现主动限制；不能通过放宽错误处理宣称支持新的版本或结构。
