# 常见环境与交付故障

本表根据用户提供的平台经验整理，并按当前DOCX实现校正；仅在对应故障出现时读取，不作为正常生成的额外步骤。报错只能作为线索，须结合本轮实际工具参数、stdout、stderr、退出码及执行状态判断。当前主流程只依赖Python标准库，不安装第三方包、不联网调用外部API，不假定固定虚拟环境、下载按钮或会话刷新机制。

所有操作继续遵守[环境自检](../SKILL.md#执行环境约束与首步自检)、[文件定位](../SKILL.md#文件定位与读取规则)与原件保护。命令中的`<skill_dir>`先替换为实际读取SKILL.md确定的真实目录；任务数据仅用宿主确认任务目录内的相对路径，不能为排错换挂载、切换安装目录或猜测备用输出位置。

## 现象、可能原因与处置

| 现象（报错或表现） | 可能原因（须核对证据） | 处置 |
|---|---|---|
| `ModuleNotFoundError: docx`或其他模块缺失 | 可能调用了另一个依赖python-docx的脚本、混用旧包/入口、安装包缺文件或解释器不符合约定；不一定是系统python3的问题。 | 本Skill不需要python-docx，先核对调用的是本包入口、包内文件齐全及解释器满足Python/Expat要求；缺内部模块时报告安装不完整。使用宿主已确认的解释器，不猜测或强制使用`scripts/.venv/bin/python`，不运行pip补装。若实际使用的是其他技能，按其真实依赖契约处理，不把本技能限制套过去。 |
| `Read-only file system`或`PermissionError` | 实际写入目标或cwd可能不可写，也可能错误写入安装目录；绝对路径本身不是只读的充分原因。 | 核对真实任务目录和CLI参数。标准新建为`run_docx_task.py create 文件名.docx`，没有`--output`，文件名不带`./`或目录；读取结果的`-o ./提取.json`及编辑输出使用各自约定的相对路径。必要写入自检失败时停止并报告，不寻找其他挂载或沙箱临时根目录绕过。归档失败与主文件写入失败分开处理。 |
| write_file写的文件，execute脚本找不到 | 两工具可能使用不同cwd、挂载、会话或虚拟文件系统，也可能文件名/路径错误；不能仅凭绝对路径判定原因。 | 当前标准新建直接传stdin，不需要write_file写规格或脚本。确有已授权输入文件时，核对两工具对同一个相对路径的解释及文件可见性；使用宿主确认的共享任务目录。相对路径也不能保证环境互通，不可见时报告工具隔离，不切换目录、复制未知文件或擅自改用旧CLI。 |
| `pip install`失败、HTTP 403或外部请求失败 | 可能离线、网络/域名策略、认证、服务端拒绝或包源问题；403不能单独证明没有网络。 | 本Skill无第三方运行依赖，禁止安装，不把pip失败当作业务生成的必要步骤。先核对是否用了错误入口。其他已授权集成若确需依赖或API，由其维护流程核对目标平台的依赖打包、解释器/ABI及域名准入；本Skill不新增`.venv`、外部调用或白名单，也不绕过访问限制。 |
| 回复或下载链接出现`<workspace>`等掩码 | 可能把展示掩码或文档占位符误作真实目录，也可能宿主只返回了掩码信息。 | 仅使用本轮可信宿主状态与实际成功摘要定位文件；已知真实输出时修正展示与链接，不为改链接重跑生成。无法确认真实位置时报告，不能拼接掩码路径。仅当宿主已确认提供工作目录文件列表/下载入口，才指导用户从该入口下载，不虚构按钮或下载链接。 |
| 更新版本后仍使用旧行为 | 当前会话可能保留旧技能副本或上下文，也可能实际安装包、所选Skill或引用资源未更新。 | 对照预期版本与宿主实际加载的SKILL.md版本、入口及相关资源，不以源码已更新代替安装已更新。若当前平台已确认“开始对话”会重新拷贝技能，可提示用户用该入口开启新会话；否则按其真实刷新/重新加载方式处理。按钮作用及热更新能力未验证时如实说明，不保证点击即可生效，不擅自覆盖安装目录或终止当前任务。 |
| 长会话后模型忘记技能用法、路径或恢复规则 | 历史可能压缩、上下文可能丢失，也可能加载了错误Skill。 | 按下节恢复真实SKILL.md及已确认任务状态，再继续。不能凭记忆猜路径、改用兼容CLI或新建同名任务；必要信息无法恢复时先说明缺口。可提示用户在保存已确认状态后开启新会话，但新会话不等于已有任务自动恢复。 |
| 流式中断、整轮无响应、`RemoteProtocolError`或超时 | 故障可能发生在模型网关、工具桥接、执行过程或结果回传；不能直接认定与技能无关、历史完整或脚本未启动。 | 先核对本轮是否已调度、进程/工具状态、完整返回、原manifest与实际主文件。仅确认未调度时才可重发；状态不明不盲目重复create，不把空返回当成功。已有原manifest按retry/resume各自契约恢复，保留原材料，不重置次数或认领旧文件。宿主证据不可得时报告执行状态未知。 |
| 生成成功但用户下载不到 | 可能写错任务位置、返回了错误链接、主文件已缺失，或宿主没有导出/下载能力；不一定是写进绝对临时路径。 | 核对本次摘要的真实`output`、主文件存在且非空，以及宿主支持的交付方式；主文件缺失不静默改读归档。修正链接时不重复生成。目录可写不等于可下载，`--check`不能验证下载功能；没有可用交付入口时如实说明，不返回猜测链接。 |
| `execute`的kwargs为空或`command Field required` | 工具参数缺失、解析/流式拼接异常，或调用被截断；不等于生成器依赖错误。 | 按[工具调用故障与宿主接入](tool-calling.md)区分外层工具参数与文档stdin，确认执行状态后有限修正；不通过安装依赖或改用print修复缺参。 |

## 仅在故障诊断时使用的自检

先定位真实脚本并使用宿主确认的解释器。仅读环境诊断使用：

```python
execute(command="python -I -S -B \"<skill_dir>/scripts/read_docx.py\" --check")
```

要求退出0且有`read-check-ok`；它检查Python/zlib/Expat/XML，不创建写入探针，不能证明目录可写。

确需排查标准新建的必要写入/锁能力时使用已有诊断入口：

```python
execute(command="python -I -S -B \"<skill_dir>/scripts/run_docx_task.py\" check")
```

要求退出0并有`auto-cleanup=available`、`output_dir=. writable=True`、`check-ok`；失败读取具体检查项后停止。它在当前任务根检查必要能力，不搜索其他可写目录，不证明可归档或可下载。正常新建的create/retry已集成同样必要自检，不为本表再增加check调用。

## 长会话恢复

1. 从可信上下文恢复本次实际读取的SKILL.md位置、任务目录、输入来源、用户授权、最终文件名、原manifest及已知结果；未确认的信息明确标缺失，不回显环境变量猜位置。
2. 重读真实SKILL.md，再按本次任务读取必要参考；不默认加载维护历史或全部排查资料。保留已有文件和任务次数，不将重新读取当作新任务授权。
3. 已知成功时核对实际输出并继续交付；失败按原next_action处理；中断/未知时先确认状态。只恢复有证据的步骤，不因上下文压缩重复生成、归档或清理。不能恢复必要状态时说明具体缺口，请用户补充或由宿主恢复，不编造成功。

## 验证边界

本页是诊断约定，不代表宿主已实现共享挂载、完整输出回传、技能刷新或文件下载。用户提供的平台经验未在真实宿主复现；本地语法、自检和结构检查不能证明这些机制可用。交付时区分脚本实际输出、执行器返回载荷与模型收到的工具结果；原始敏感配置和内部归档信息不得转贴给最终用户。
