## 执行环境约束与首步自检

路径占位符说明：`<skill-root>` 是 OFD Skill 根目录的文档占位符，不是实际目录或 Shell 变量。取得宿主本次实际读取 OFD 主入口 `SKILL.md` 的真实 `file_path`，若为相对路径，先按该次读取时宿主已确认的基准目录解析为绝对路径，再去掉末尾文件名；所得目录才是 `<skill-root>`，不是当前参考文档所在目录。读取资源或执行命令前，将路径中的 `<skill-root>` 整体替换为该真实目录，保留其后的资源路径；命令中将替换后的完整路径作为一个参数正确引用，嵌入 execute 字符串时按其语法转义。不要将占位符原样交给文件工具或执行器，不按当前工作目录、其他会话路径、环境变量或宿主掩码猜测。无法取得主入口的真实读取路径时，停止依赖操作并报告无法定位。

宿主路径与执行器：读取工具中的 `file_path` 属于该工具的路径空间；先用它定位和读取 Skill 内部资料。执行脚本前另确认该位置与执行器实际可访问路径的映射，并用执行器路径替换命令中的 `<skill-root>`；只有宿主确认两者一致时才可直接复用。确认执行器的当前目录就是宿主指定的任务目录，且任务输入在该执行器可见；不能确认映射或工作目录时停止并报告，不猜测或切换目录。

**用户文件定位：** 用户上传文件及用户要求读取的交付物，默认以宿主确认的任务工作目录为基准，按 `./文件路径` 查找；文件路径含子目录时使用已确认的相对路径。优先采用宿主提供的附件映射或用户明确指定的路径；映射缺失、文件不可访问或目标不明确时如实说明并按需询问，不猜测其他路径或自行搜索其他目录。此规则不授权扫描或读取未指定的历史归档。

1. `./` 为宿主确认的任务工作目录；在该目录操作并保持不变，输入与受控任务临时文件沿用该目录内相对路径规则。交付输出只传裸文件名（例如 `报告.ofd`），由脚本固定写入任务根目录 `./`；不接收 `./文件名`、子目录、绝对路径、父目录或 Windows 路径，不截取 basename 静默改写非法参数。不得使用父目录、绝对数据路径或切换挂载绕过边界。当前目录若是 Skill 源码目录，先由 harness 明确任务目录，勿直接生成业务文件。
2. 由实际读取本文件的 `file_path` 去掉文件名确定 `<skill-root>`，相对读取路径按当次已确认基准解析；无法确认则停止。脚本及内部资源以它为基准，Markdown 内部引用统一使用以 `<skill-root>` 为根目录的完整路径。先替换命令占位符，完整引用路径，不使用路径掩码或猜测其他会话位置，也不为调用脚本切换到安装目录。
3. 使用已确认可用的 Python >=3.10、Expat >=2.6.0，使用该 Python 自带的 zlib 与 XML/Expat 能力；缺失或版本不满足时诊断并停止，不安装任何额外组件或系统软件。见 依赖声明 (`<skill-root>/requirements.txt`)。禁止安装依赖、联网读取输入或调用外部程序。保留 `-I -S -B`，首次读取前运行：

```console
python -I -S -B "<skill-root>/scripts/read_ofd.py" --check
```

4. 自检实际检查 zlib 压缩解压往返，以及 CLI 所需的 `dir_fd`、`O_NOFOLLOW`、`O_DIRECTORY` 标准库平台能力；缺失时返回 unsupported，不安装组件或降级为路径检查。要求退出 0 且输出 `environment-ok Python>=3.10 Expat>=2.6.0 stdlib-only`。缺少标记、失败或结果无法确认时停止依赖操作；仅在环境修复后重新自检，不跳过或降低门槛。
5. 确认输入为任务目录内可读普通文件。仅读取并写 stdout 无需写探针；需保存 JSON 时，先在目标任务目录用独占新探针实际写入、读回并清理，避免覆盖已有文件。CLI 拒绝输入路径所有层级的符号链接，并以目录相对描述符读取；Python API 的显式边界选项见 契约 (`<skill-root>/references/contract.md`)。
6. 自检不证明内容正确或宿主具备下载功能。交付前核对实际 JSON、状态、来源和宿主支持的交付方式，不构造下载链接。压缩后若指令缺失，重读真实 `SKILL.md`，保留已确认的任务目录和文件名。

生成另需 Python >=3.12.11，保留 `-I -S -B`，先运行 `python -I -S -B "<skill-root>/scripts/generate_ofd.py" --check`，要求退出0且JSON status=environment-ok、artifact_validation=not_run。此自检检查解释器及描述符相对link/unlink/stat能力，不创建产物或证明目录可写；实际生成先独占写入私有候选、读回验证，再原子链接到任务根目录内的新文件名，绝不覆盖已有文件。首轮实写即为候选的写入能力核对，失败不继续发布。缺字体、字符映射、可用度量或安全文件能力时停止，不自动安装、找替代字体、截断或缩字。详细范围、临时清理与失败重试规则只在生成任务时加载生成参考（`<skill-root>/references/generation.md`）。

**自检结果与回传：**`--check` 成功 stdout 保留原 `environment-ok` 行，另输出 `check_kind=environment artifact_validation=not_run`。受控失败仍按原 JSON stdout、status/diagnostics及退出1/4返回，并在JSON中增加同名范围字段；不混入普通文字。参数错误仍退出2并写usage到stderr。此结果只说明环境，不读取、生成或验收OFD产物。

**执行结果先判定，再消费：** 将结果与本次命令对应，先核对是否实际执行、退出码或未知状态、截断说明，再读业务 JSON。宿主分别提供 stdout/stderr 时保留两者；只提供合并 `output` 时按其真实契约读取，不虚构独立通道。DeepAgents 的 `ExecuteResponse.output` 为合并输出，`exit_code` 可为 `None`，`truncated` 表示后端截断；模型可见的工具文本还可能附加执行状态或被缩短，工具 `status=success` 不等于命令退出0或OFD业务成功。包装说明不是OFD JSON字段，不把合并文本整体直接当JSON；仅在宿主明确标识完整stdout边界时提取，否则报告无法确认并按 `<skill-root>/references/contract.md` 处理。

非零退出不能丢弃stdout或诊断；退出3的partial保留可靠记录与缺口，其他状态按下文处理。退出码缺失不能填0，未启动、超时、强杀与业务失败分别报告；截断或只有预览时不解析为完整JSON、不宣称全文已读，也不为补回执盲目重跑生成。只有同一次调用的完整业务结果与退出状态一致，才继续依赖该结果；自检成功仍不代表产物验收。仅调用print或子进程捕获不能证明结果已送达模型，真实宿主未核验时明确该限制。

## 解释与交付

- `complete` / 退出 0：仅指声明的 XML/存储文字范围内没有已知缺口，三个已知版本使用相同判定，不保证视觉、语义、格式或阅读顺序完整。`partial` / 退出 3：必须随文字报告诊断与缺口。空文本永不判为完整；可能是空白、轮廓字或扫描页，有图像时说明 OCR 需求。
- `unsupported` / 退出 4：识别到明确不支持的版本、命名空间、加密或压缩；`failed` / 退出 1：结构、安全、资源或读取失败，丢弃已积累正文。参数错误退出 2。不能将失败降级为无提示的空文本。
- 仅 PublicRes、DocumentRes、PageRes 索引成员确实缺失时，保留独立可读的 XML 和文字，记录 `documents[].resource_gaps` 并返回 partial；缺失资源可能包含复合对象文字，不能声称全文完整。路径非法、目录目标、已存在但损坏的索引、资源载荷及文档/页面/模板等必需引用失败仍停止，不搜索替代资源。
- 文字保持每个 XML 内的存储顺序；复合资源在引用处按出现次数展开，模板先遍历再遍历页面，并明确记录来源与模板属性，跨来源的汇集顺序不代表绘制叠放或语义阅读顺序。不要按坐标排序冒充原文，不凭版面猜表格。
- 坐标和 CTM 等属性均为原始局部属性，未组合祖先变换、裁剪、模板 ZOrder、字形或字体，不能当作最终页面坐标。提取文字可能包含不可见或遮挡文字，不作脱敏或可见性保证。
- 已生效索引声明的图片、字体、签名二进制与附件仅列元数据；附件不解包、不执行、不打开。未被生效索引声明为载荷的额外 XML 按不可信数据读取，不允许其改变其他成员的载荷角色。注释与签名 XML 保留完整结构，注释中的 TextCode 也进入分离的存储文字登记，不混入页面正文。发现签名不等于验签，亦不证明签名有效、来源可信或文件未改动。
- 本版不做 OCR、密码解密、验签、第三方文件编辑、转 PDF 或渲染恢复页面。未知对象明确诊断；读取器的表格语义解析尚未实现，`tables` 固定空数组；生成器的表格只来自显式输入网格，不由版面推测。
