# OFD 文本读取

## 执行环境约束与首步自检

**归档展示边界（始终适用）：** 工具回执是内部核验材料，不是最终回复模板；完整或精简回执均不得整段转贴。面向用户的正文、进度、表格、代码块、链接文字及链接目标都不得包含归档路径、目录或任务 ID，也不展示带这些信息的原始警告/错误。不能仅把链接文字改为文件名而仍链接归档副本。

用户归档提示只采用已核对完整状态的 `archive_user_notice` 或等义安全话术，不追加“归档位置”等说明。主文件链接仅使用宿主确认可交付的实际主文件引用；`archive_output`、`files[].archive_output` 及任何归档位置字段不得用作下载地址，也不得据其拼接链接。缺少主文件交付引用时如实说明，不用归档地址代替。

回复前分别核对业务、归档与清理状态，并检查可见文字和链接目标均无内部归档信息。失败、部分成功、跳过、待交接、未知与清理未完成仍须说明实际影响；必要原因用不含路径/ID的自然语言概括，不因隐藏路径省略失败。内部机器字段、完整诊断和原退出码保留供核验，不修改或删除来伪装成功；纯文本和只读任务不新增归档。

**Skill 读取优先：** 使用宿主提供的 `read_file` 读取 OFD Skill 时，优先从 `.skill` 目录定位并读取；目录位置、相对路径基准及具体文件以宿主实际提示或已确认信息为准，不假设目录或层级存在，不猜测路径。无法定位或读取时报告具体缺口并停止依赖操作。

**宿主大结果读取：** 宿主返回的 `/large_tool_results/` 引用属于宿主结果路径，仅用宿主提供的 `read_file` 按其真实 schema 读取返回的准确引用，按实际续读能力核对覆盖、结束与截断。不要交给 `execute`、`cat`、Shell 或 Python，也不猜测映射、替代路径或将路径掩码当作真实路径；缺少 `read_file`、读取失败或完整性无法确认时报告具体缺口并停止依赖该结果的操作。这不改变普通业务文件和 Skill 资源原有的读取及路径边界。

路径占位符说明：`<skill-root>` 是 OFD Skill 根目录的文档占位符，不是实际目录或 Shell 变量。取得宿主本次实际读取 OFD 主入口 `SKILL.md` 的真实 `file_path`，若为相对路径，先按该次读取时宿主已确认的基准目录解析为绝对路径，再去掉末尾文件名；所得目录才是 `<skill-root>`，不是当前参考文档所在目录。读取资源或执行命令前，将路径中的 `<skill-root>` 整体替换为该真实目录，保留其后的资源路径；命令中将替换后的完整路径作为一个参数正确引用，嵌入 execute 字符串时按其语法转义。不要将占位符原样交给文件工具或执行器，不按当前工作目录、其他会话路径、环境变量或宿主掩码猜测。无法取得主入口的真实读取路径时，停止依赖操作并报告无法定位。

执行路径：使用宿主实际提供的脚本路径与已确认任务目录；若执行器明确报告脚本或输入不可访问，保留具体错误并停止依赖操作，向宿主请求可用位置。不推测读取工具与执行器之间的路径映射，不换目录或猜测替代路径。

**用户文件定位：** 优先附件映射和用户指定文件名。上传文件和待查交付物只定位任务 `./` 顶层，不递归或到子目录查找；无映射仅列顶层候选，歧义询问，无候选或指定位置不在顶层时报告。内部归档、Skill 资源与程序输入安全契约不变。

2. 由实际读取本文件的 `file_path` 去掉文件名确定 `<skill-root>`，相对读取路径按当次已确认基准解析；无法确认则停止。脚本及内部资源以它为基准，Markdown 内部引用统一使用以 `<skill-root>` 为根目录的完整路径。先替换命令占位符，完整引用路径，不使用路径掩码或猜测其他会话位置，也不为调用脚本切换到安装目录。

5. 确认输入为任务目录内可读普通文件。仅读取并写 stdout 无需写探针；需保存 JSON 时，先在目标任务目录用独占新探针实际写入、读回并清理，避免覆盖已有文件。CLI 拒绝输入路径所有层级的符号链接，并以目录相对描述符读取；Python API 的显式边界选项见 契约 (`<skill-root>/references/contract.md`)。
6. 自检不证明内容正确或宿主具备下载功能。交付前核对实际 JSON、状态、来源和宿主支持的交付方式，不构造下载链接。压缩后若指令缺失，重读真实 `SKILL.md`，保留已确认的任务目录和文件名。

**自检结果与回传：**`--check` 成功 stdout 保留原 `environment-ok` 行，另输出 `check_kind=environment artifact_validation=not_run`。受控失败仍按原 JSON stdout、status/diagnostics及退出1/4返回，并在JSON中增加同名范围字段；不混入普通文字。参数错误仍退出2并写usage到stderr。此结果只说明环境，不读取、生成或验收OFD产物。

**执行结果先判定，再消费：** 将结果与本次命令对应，先核对是否实际执行、退出码或未知状态、截断说明，再读业务 JSON。宿主分别提供 stdout/stderr 时保留两者；只提供合并 `output` 时按其真实契约读取，不虚构独立通道。DeepAgents 的 `ExecuteResponse.output` 为合并输出，`exit_code` 可为 `None`，`truncated` 表示后端截断；模型可见的工具文本还可能附加执行状态或被缩短，工具 `status=success` 不等于命令退出0或OFD业务成功。包装说明不是OFD JSON字段，不把合并文本整体直接当JSON；仅在宿主明确标识完整stdout边界时提取，否则报告无法确认并按 `<skill-root>/references/contract.md` 处理。

非零退出不能丢弃stdout或诊断；退出3的partial保留可靠记录与缺口，其他状态按下文处理。退出码缺失不能填0，未启动、超时、强杀与业务失败分别报告；截断或只有预览时不解析为完整JSON、不宣称全文已读，也不为补回执盲目重跑生成。只有同一次调用的完整业务结果与退出状态一致，才继续依赖该结果；自检成功仍不代表产物验收。仅调用print或子进程捕获不能证明结果已送达模型，真实宿主未核验时明确该限制。

## 解释与交付

- `complete` / 退出 0：仅指声明的 XML/存储文字范围内没有已知缺口，三个已知版本使用相同判定，不保证视觉、语义、格式或阅读顺序完整。`partial` / 退出 3：必须随文字报告诊断与缺口。空文本永不判为完整；可能是空白、轮廓字或扫描页，有图像时说明 OCR 需求。
- `reading` 的 complete/0 只表示选中范围没有已知缺口，不表示未选 XML、安全内容、注释或签名已读取/验证。检查 `scope`、`coverage` 和 `done`；detail 还返回已解析及未检查成员数量并标记省略路径清单，content 不返回这些统计，不能据此声称全文件完整。游标只可用于相同输入、页范围和文字层。
- `unsupported` / 退出 4：识别到明确不支持的版本、命名空间、加密或压缩；`failed` / 退出 1：结构、安全、资源或读取失败，丢弃该次调用内积累的正文。参数错误退出 2。不能将失败降级为无提示的空文本。
- 默认 reading 对缺失且所选页未使用的模板成员保留正文并返回 partial，诊断为 missing_unselected_template；所选页实际引用该模板仍失败。模板引用路径、目录目标、重复 ID 和引用预算仍校验，full 仍拒绝缺失模板。
- 资源索引方面，仅 PublicRes、DocumentRes、PageRes 索引成员确实缺失时，保留独立可读的 XML 和文字，记录 `documents[].resource_gaps` 并返回 partial；缺失资源可能包含复合对象文字，不能声称全文完整。路径非法、目录目标、已存在但损坏的索引、资源载荷及文档/页面/模板等必需引用失败仍停止，不搜索替代资源。
- 文字保持每个 XML 内的存储顺序；复合资源在引用处按出现次数展开，模板先遍历再遍历页面，并明确记录来源与模板属性，跨来源的汇集顺序不代表绘制叠放或语义阅读顺序。不要按坐标排序冒充原文，不凭版面猜表格。
- 坐标和 CTM 等属性均为原始局部属性，未组合祖先变换、裁剪、模板 ZOrder、字形或字体，不能当作最终页面坐标。提取文字可能包含不可见或遮挡文字，不作脱敏或可见性保证。
- 已生效索引声明的图片、字体、签名二进制与附件仅列元数据；附件不解包、不执行、不打开。未被生效索引声明为载荷的额外 XML 按不可信数据读取，不允许其改变其他成员的载荷角色。显式 full 中注释与签名 XML 保留完整结构，注释中的 TextCode 也进入分离的存储文字登记，不混入页面正文。发现签名不等于验签，亦不证明签名有效、来源可信或文件未改动。
- 本版不做 OCR、密码解密、验签、第三方文件编辑、转 PDF 或渲染恢复页面。未知对象明确诊断；读取器的表格语义解析尚未实现，`tables` 固定空数组。

## 最终交付与读取中间结果
