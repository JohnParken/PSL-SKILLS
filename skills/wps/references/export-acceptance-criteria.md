# WPS 文档导出验收标准

路径占位符说明：`<skill-root>` 是本 Skill 根目录的文档占位符，不是实际目录或 Shell 变量。取得宿主本次实际读取主入口 `SKILL.md` 的真实 `file_path`，若为相对路径，先按该次读取时宿主已确认的基准目录解析为绝对路径，再去掉末尾文件名；所得目录才是 `<skill-root>`。读取资源或执行命令前，将路径中的 `<skill-root>` 整体替换为该真实目录，保留其后的资源路径；命令中将替换后的完整路径作为一个参数正确引用。无法取得主入口的真实读取路径时，停止依赖操作并报告无法定位。

## 四级验收体系

任务输入输出以宿主确认的任务工作目录为基准。导出各级验收分别报告，不能仅凭进程退出0认定完整成功。

### 第一级：转换与发布

转换器应实际产生本次独占候选。脚本先验签名、受支持内容及后缀，随后原子发布；来源不得被覆盖，失败不以已有旧文件代替结果。导出 CLI 的 success／partial／失败分别退出0／3／1；参数错误退出2。LibreOffice 子进程退出码与导出 CLI 退出码是不同层级。

### 第二级：格式与后缀

| 实际字节 | 可写后缀 | 验收 |
|---|---|---|
| RTF | `.rtf/.wps` | 实际 RTF 解析；截断、无效编码等恢复问题阻止发布；受支持的合并几何缺口或附加区域遗漏可返回 partial |
| MS-DOC/CFB | `.doc/.wps` | 通过有界 CFB、WordDocument、FIB 与主文字解析；不能只检查文件头或目录名 |
| OOXML Word | 不属于此导出器的输出 | 可作转换输入或读取；不能改名 `.wps/.doc` 当作导出成功 |

`inspect` 是写入候选校验：valid=true 且 partial=false 退出0，valid=true 且 partial=true 退出3，其他退出1。输入读取仍由 `<skill-root>/scripts/read_wps.py` 按内容识别，RTF 或 OOXML 使用历史 `.doc` 后缀不因此拒读。两种规则用途不同。

### 第三级：正文与诊断

`verify_readback` 对 RTF、MS-DOC、OOXML 均调用实际 read_wps CLI，兼容 MS-DOC 的字符串段落及 RTF/OOXML 的段落对象。保留真实退出码、诊断、遗漏及 reading_assessment；预览最多5段，每段100字符，不能冒充全量内容。读取状态与退出码必须一致：ok／0 对应 readback-ok，partial／3 对应 readback-partial；错误JSON、错误段落结构、状态与退出码不一致均不算通过。

导出 `--verify-read` 接到 partial 时保持顶层 partial；回读失败则返回 readback-failed／退出1并指出产物已经存在，不将其标记完整成功。来源的 partial 和 auto 回退也不会因输出正文可读而被抹去。

关键标题、金额、表格与范围仍须按任务对照，主文字回读并非转换前后完整内容一致性证明。此导出器不具备声明式创建／重排编辑的完整计划内容账本；源样式继承、未支持对象、域新鲜度与页面版式仍未验证。

### 第四级：客户端与平台

在目标 WPS/Word 客户端实际检查打开提示、字体、段落、跨页表格、页眉页脚、图片及再次保存。Linux、Windows、macOS 和不同渲染器分别记录测试条件与结果；未执行的平台或未成功的转换不记为通过。

标准库合成测试与已有样本的读取回归能证明相应读取和调用契约，不能代替真实 LibreOffice 二进制生成或客户端视觉验收。外部转换器不可用时明确报告阻塞；不要把 RTF `.wps` 或模拟 CFB 文件描述为已验收的原生 DOC 生成。
