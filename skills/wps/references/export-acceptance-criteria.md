# WPS 文档导出验收标准

路径占位符说明：`<skill-root>` 是本 Skill 根目录的文档占位符，不是实际目录或 Shell 变量。取得宿主本次实际读取主入口 `SKILL.md` 的真实 `file_path`，若为相对路径，先按该次读取时宿主已确认的基准目录解析为绝对路径，再去掉末尾文件名；所得目录才是 `<skill-root>`。读取资源或执行命令前，将路径中的 `<skill-root>` 整体替换为该真实目录，保留其后的资源路径；命令中将替换后的完整路径作为一个参数正确引用。无法取得主入口的真实读取路径时，停止依赖操作并报告无法定位。

## 四级验收体系

导出结果必须经过分层验证，严禁仅凭进程退出码判定导出成功：

### 第一级：转换完成（Process Execution）

- 导出进程或 Python 转换模块正常执行，返回码为 0。
- 目标路径确实生成了预期的 `.wps` 文件，且文件大小大于 0 字节。
- 标准错误流中未报告致命未捕获异常。

### 第二级：结构符合预期（Document Structure Integrity）

通过底层结构分析验证生成的文件具备受支持的文档格式，**严格拦截直接将 OOXML ZIP 包改名为 `.wps` 的伪造文件**（文件头以 `PK\x03\x04` 开头）：
1. **RTF 规范流格式（纯 Python 标准库后端生成）**：
   - 文件头必须以 `{\rtf1` 开始。
   - 包含完整的字体表定义（`\fonttbl`），涵盖中西文字体映射。
   - 结尾具备合法的闭合花括号 `}`。
2. **CFB 复合二进制容器格式（LibreOffice 兼容导出生成）**：
   - 文件前 8 字节必须为 OLE/CFB 头部签名 `0xD0CF11E0A1B11AE1`。
   - 能够按标准 CFB 规范读取目录条目并包含 `WordDocument` 流。
   - `WordDocument` 流前 2 字节（`wIdent`）必须为 `0xA5EC`，基准 FIB 版本在受支持的范围内。

### 第三级：内容通过检查（Content Readback Validation）

对生成的 `.wps` 执行文本和关键结构回读核对：
1. **段落与标题提取**：提取导出的正文，确认主标题、各级子标题完整存在。
2. **表格内容核验**：确认重要表格数据、数字和关键单元格文本未发生丢失或截断。
3. **诊断标记审阅**：回读若出现 `partial` 或警告，必须在诊断结果中保留说明，不可隐瞒降级。

### 第四级：目标 WPS 实机验收（Target Client Verification）

在真实的 WPS 客户端（Linux 桌面/Windows 桌面）中打开生成文档：
1. **打开无弹窗报错**：文档打开时不触发“文件已损坏”、“需要修复”或“存在不受信任内容”提示。
2. **版式与字体**：中文字体（宋体、仿宋、黑体、楷体等）正确匹配，段落行距、段前段后间距符合预期。
3. **复杂版面保真**：跨页表格表头重复、页眉页脚页码计算、图片位置排布保持正确。
4. **二次保存测试**：在 WPS 客户端内进行微调并保存，确认文件未损坏。
