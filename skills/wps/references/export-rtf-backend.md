# RTF 规范流纯 Python 导出机制

路径占位符说明：`<skill-root>` 是本 Skill 根目录的文档占位符，不是实际目录或 Shell 变量。取得宿主本次实际读取主入口 `SKILL.md` 的真实 `file_path`，若为相对路径，先按该次读取时宿主已确认的基准目录解析为绝对路径，再去掉末尾文件名；所得目录才是 `<skill-root>`。读取资源或执行命令前，将路径中的 `<skill-root>` 整体替换为该真实目录，保留其后的资源路径；命令中将替换后的完整路径作为一个参数正确引用。无法取得主入口的真实读取路径时，停止依赖操作并报告无法定位。

## 核心机制与兼容性原理

在无外部办公软件（如 LibreOffice）且无法安装第三方扩展包的环境下，金山 WPS 文字客户端对文件类型的容错与解析机制提供了最高效的导出路径：
1. **格式嗅探机制**：金山 WPS 客户端打开 `.wps` 扩展名文件时，优先读取前导魔数。当识别到 `{\rtf1`（Rich Text Format 富文本流）时，WPS 会静默调用其内置的渲染核心进行版式呈现。
2. **零弹窗警告**：WPS 客户端完全信任并原生支持规范的 RTF 流，不会弹出“文档损坏”、“需要修复”或“存在不受信任内容”提示，交互体验与原生二进制文件一致。
3. **二次保存升级**：用户在 WPS 中查看、编辑并点击保存时，WPS 客户端会自动按用户当前软件版本规范将文档升级存储。

## 中文字体与排版映射

RTF 流在纯 Python 标准库中直接生成，通过严格的控制符精确复现公文与严肃商业报告排版：
- **字体映射表（`\fonttbl`）**：
  - `\f0`: 宋体（SimSun，`\fcharset134`）
  - `\f1`: 黑体（SimHei，`\fcharset134`）
  - `\f2`: 仿宋（FangSong，`\fcharset134`）
  - `\f3`: 楷体（KaiTi，`\fcharset134`）
  - `\f7`: 微软雅黑（Microsoft YaHei，`\fcharset134`）
  - `\f8`: 仿宋_GB2312（FangSong_GB2312，`\fcharset134`）
- **Unicode 转义规范**：
  - 声明 `\uc1`（每个 Unicode 字符后跟随 1 字节 ANSI 回退占位符 `?`）。
  - 中文码元按 RTF 规范转换为有符号 16 位整数 `\uN?`，彻底消除不同操作系统环境下的字符集乱码风险。
- **页面几何尺寸（A4 标准）**：
  - 纸张宽度：`\paperw11906`（210mm，以 1 磅 = 20 缇为基准）
  - 纸张高度：`\paperh16838`（297mm）
  - 公文标准边距：上 2098 缇（3.7cm）、下 1984 缇（3.5cm）、左 1587 缇（2.8cm）、右 1474 缇（2.6cm）。
- **表格与跨页控制**：
  - 表头行重复：通过 `\trhdr` 声明表头行，跨页自动在新页顶端重现表头。
  - 行不截断控制：`\trkeep` 保证整行内容不被物理页面中途切断。
  - 单元格合并：支持横向合并（`\clmgf` 首格 / `\clmrg` 后续格）与纵向跨行合并（`\clvmgf` / `\clvmrg`）。

## 运行时优势

1. **绝对零依赖**：仅使用 Python 标准库中的 `zipfile`、`xml.etree.ElementTree`、`struct`，无需系统安装 LibreOffice、Java 或 C++ 动态库。
2. **毫秒级性能**：相较于拉起桌面办公软件无头进程（通常需 2~5 秒），纯 Python 流式转换仅需 10~50 毫秒。
3. **确定性与稳定性**：不依赖外部守护进程或临时显示虚拟环境（如 Xvfb），完全避免因进程崩溃、字体缺失或端口争用导致的转换失败。
