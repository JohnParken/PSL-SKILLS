# 读取验收、边界与设计来源

路径占位符说明：`<skill-root>` 是 pdf Skill 根目录的文档占位符，不是实际目录或 Shell 变量。取得宿主本次实际读取 pdf 主入口 `SKILL.md` 的真实 `file_path`，若为相对路径，先按该次读取时宿主已确认的基准目录解析为绝对路径，再去掉末尾文件名；所得目录才是 `<skill-root>`，不是当前参考文档所在目录。读取资源或执行命令前，将路径中的 `<skill-root>` 整体替换为该真实目录，保留其后的资源路径；命令中将替换后的完整路径作为一个参数正确引用，嵌入 execute 字符串时按其语法转义。不要将占位符原样交给文件工具或执行器，不按当前工作目录、其他会话路径、环境变量或宿主掩码猜测。无法取得主入口的真实读取路径时，停止依赖操作并报告无法定位。

## 每轮读取如何验收

| 核对项 | 合格条件 |
|---|---|
| 来源与覆盖 | 输入身份与用户材料相符；请求、已处理、遗漏页的对应关系清楚，引用使用物理页号。 |
| 正文 | 关键人名、日期、金额及结论和原页一致；怀疑乱码、扫描或阅读顺序时查看预览，不根据局部文字补齐全文。 |
| 文字位置 | bbox、字体及页面旋转可用于定位；不把几何位置当作语义标签。区域结果确实来自所选范围。 |
| 表格 | 抽查标题、行列、表头、数字和单位；区分空字符串、空单元格和未恢复的合并关系，跨页内容逐页保留。 |
| 图片与预览 | 区分显示实例与可能未显示的页资源，不能臆测对应关系；导出图片可解码，预览页号与范围正确。图像内容需视觉检查后才能解释。 |
| 导出 | JSON 可解析、Markdown 可读、资产引用实际存在；返回列表中的文件才能交付。 |
| 状态 | 读取全部 warnings 和 diagnostics，保留 `partial` 与缺失原因；自检、内容验收、归档和清理分别判断。 |
| 源文件 | 只读访问，不保存或重写源 PDF；开发回归以输入哈希前后相同验证。 |

stdout-only 场景核对完整 JSON，不要求生成文件。仅请求某几页时，“完成”只覆盖这些页；没有请求的表格、图片或预览不是“未检出”。输出目录存在也不证明生成完成。

## 限制如何解释

扫描、字体映射异常和混合内容的诊断是启发式。大量图片、极少文字或异常字符可以提示需要 OCR/视觉核对；没有警告不能证明每个可见字符均已正确提取。空文本可能来自真实空白、图片、矢量绘制文字、损坏映射或所选区域，不能单凭空字符串定性。

本阶段保留原生文字、页内表格和几何信息。多栏、竖排、页眉页脚、数学公式、带水印/隐藏字层、复杂合并表格以及图表语义都可能需要人工核对。预览用于查看页面，不进行 OCR；表格输出不自动跨页拼接或补全缺失数字。

图片导出处理页资源词典中可提取的栅格图片，可能包含未显示的资源；显示实例只保留几何信息，两者不强行关联。区域裁剪时不导出整幅资源，透明蒙版单独输出。矢量图、渐变、剪裁蒙版和复杂透明效果不保证能独立导出为原样图片。页面预览更接近可见内容，但它是栅格渲染结果，不代表可编辑对象。输出图片可能采用可解码格式而非原始编码字节，不承诺原始资源逐字节保真。

密码来自显式指定的密码文件；无法打开的加密文档报告错误，不尝试猜密码。对损坏 PDF 的自动修复行为依赖引擎，不能以“能打开”推断源文件完全正常。资源预算限制常见超量任务；复杂原生解析仍由宿主超时和进程资源管理兜底。

## 维护回归

以下是仓库维护命令，基准目录是当前仓库根目录；仓库的 `tests/` 与 `skills/skill-development-standards/` 不属于 PDF 独立 Skill 包，不能按安装目录猜测这些路径。

```console
python -B -m unittest discover -s tests -p test_pdf_reader.py -v
python -I -S -B skills/skill-development-standards/scripts/check_skill.py skills/pdf --strict
```

功能测试使用标准库 unittest、固定版本 PyMuPDF，以及仅开发夹具需要的 ReportLab/Pillow；后两者不是 PDF CLI 的运行依赖。夹具覆盖独立生成的中英文、数字、原生表格、嵌入图片，以及扫描、混合、空白、加密和旋转页。维护时同时检查正文/坐标/页选择/区域、表格、图片与预览、JSON/Markdown、只读源文件、预算、错误、路径与禁止覆盖行为。

结构检查只验证 Skill 元数据、路径和资源组织，不能代替功能测试。合成测试通过也不能替代真实复杂 PDF 的正确率测量、人工视觉核对、真实模型选 Skill 或其他操作系统验证。后续修改引擎版本、结果 schema、诊断或参数时须重跑受影响的行为，不直接沿用旧结论。

## 本轮实际验证

2026-11-02 在 Linux 6.18.57-x86_64 / glibc 2.39、Python 3.12.14、PyMuPDF 1.26.6 环境执行。最终功能回归为 **36 项全部通过，0 失败、0 错误、0 跳过，真实退出码 0，用时 31.701 秒**，覆盖导出 stdout 摘要预算、安装树内数据路径拒绝、创建后打开目录失败的清理，以及自检与读取的输入预算一致性。下述证据记录的实现哈希对应最终执行版本。严格结构检查退出 0。Pylint 3.3.9 对四个运行脚本及测试文件执行 C0103、C0301、C0321 定点规则，行长上限 200，退出 0 且无诊断；这不是全量 Pylint 检查。Pylint、ReportLab 4.4.9、Pillow 12.3.0 仅用于本轮开发验证，没有加入运行依赖。

真实样本使用中国人民银行公开的《中国货币政策执行报告 2024 年第二季度》，官方来源 <https://www.pbc.gov.cn/goutongjiaoliu/113456/113469/5427706/2024080916563291755.pdf>。源文件共 58 页、1275941 字节，SHA-256 为 `6859bb7e6d3b67c971c000d95093ad93838dbcd9d41b476b9864ea7bebeb6f1c`。仅抽查物理第 1、2、9 页：先通过独立页面检索和 Poppler 渲染建立预期，再运行本入口；8 项文字检查和 3 行表格预期全部通过，源哈希保持一致，第 9 页导出预览与独立 Poppler 页面人工对照通过。该页提取两张表，结构分别为 6×4 与 5×2。没有将原始 PDF 放入 Skill 包或仓库。

证据记录为仓库根目录下的 `tests/pdf_phase1_verification.json` 和 `tests/pdf_real_sample_oracles.json`，不是运行依赖或安装后资源；前者保留具体命令、实际结果、测试时实现哈希及未验证范围。报告中的“WPS 文字”来自样本的 creator 元数据，未运行 WPS 应用。

本轮将安装副本设置为文件 444/目录 555，重复运行前后文件名与字节保持一致；执行 UID 为 0，因此仅证明实际运行未改写，不能声称已证明内核对非特权写入的强制阻止。未运行 Windows/macOS、Acrobat/WPS GUI 或生产宿主自动选 Skill；未逐字验收这份报告全部 58 页，也未测得任意 PDF 的通用准确率。子进程测试分别捕获了 stdout/stderr，当前执行工具合并展示两通道，生产宿主的真实回传分离仍须单独核对。

## 依赖和设计来源

运行依赖固定为 PyMuPDF==1.26.6，Python >=3.10，声明见 `<skill-root>/requirements.txt`。使用 `import pymupdf`，不依赖同名无关的 `fitz` 包。此版本的 Python 下限和双许可证说明见官方发布页 <https://pypi.org/project/pymupdf/1.26.6/>；分发时第三方库的 AGPL/商业许可仍按其自身条款处理，本 Skill 不捆绑第三方二进制。

本实现独立编写，没有复制第三方 Skill 脚本，也没有复制或隐式导入本仓库其他业务 Skill。阅读和交付职责分开，通过实际定位的公共 `artifact-lifecycle` 独立交接。阅读流程、CLI、JSON 结构、预算和状态契约是本阶段新增实现。
