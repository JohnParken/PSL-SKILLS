# 演示文稿任务路由

路径占位符说明：从宿主实际读取主入口 `SKILL.md` 的真实 `file_path` 去掉文件名确定 `<skill-root>`；相对读取路径先按本次已确认的基准目录解析。使用前替换占位符并引用完整路径，参考文档目录不是根目录；无法定位时停止并报告，不猜路径。

本页是固定上游工作流的 TL 安全入口适配，不是把上游全部命令或 Web UI 原样开放。当前可调用的命令只以 `<skill-root>/references/usage.md` 为准；服务和素材访问仍需授权。模板操作须通过独立发行完整性和质量校验；本版不提供旁白、字幕或视频处理。

## 新建：普通与 Quick

普通流程先根据已有材料确定受众、沟通目标、页序、证据、图表口径及版式，再编写完整 SVG 页面，**导出前可用 `text-measure` 估算文本换行与边界、用 `svg-check` 预检单页 SVG**，通过 convert/build 导出。运行环境完全离线，严禁尝试联网检索或发送资料；只基于用户提供的本地材料创作，缺少会影响结论的事实时直接标注缺口或向用户确认。SVG 必须承载全部可见设计，spec/模板不能补足导出时缺失的页面内容；需要图表或风格参考时可按需查阅 `<skill-root>/assets/visualizations/charts/charts_index.json` 与 `<skill-root>/assets/template-catalogs/`。

明确要求快速、直接 SVG→PPTX 或跳过策略时采用 Quick：减少规划文档和互动，直接完成有依据的页序、SVG、质量核对与导出；不能跳过事实、路径、资源、许可证和交付验证。页数少不是自动选择 Quick 的理由。上游 Confirm UI、模板库自动发现和服务器不是本包默认操作。

仅当任务根目录已提供离线模板/图标 ZIP 时，按 `<skill-root>/references/offline-assets.md` 查询并选择精确 ID，保留署名与权利限制；未提供素材包时直接手工编写 SVG 或使用用户本地图片。build 通过明确 resources 映射解析本次图片和图标；保留已有路径、原生形状与普通可编辑文字。需要显式文字轮廓时仅使用 usage 中受限 text-outline 路径，生成 SVG 后再 convert；不等价复杂 shaping。几何布尔只限明确支持的子集，不静默替换或自动安装通用后端。

## 图片页面重建

当图片是待还原的整页画面，采用 Quick 的图片重建分支。先确认页面边界、顺序、方向和画幅，仅在当前宿主模型具备直接看图能力且用户已提供本地图片时分层重建文字/形状/图表；不依赖无头浏览器截图或外部 OCR 服务，无法准确读取的内容明确标记，不捏造。原生重建不等于把整页图片贴满，只嵌入获准使用的图像内容。由于无无头浏览器与客户端渲染环境，不执行导出后的视觉截图比对（`visual_validation=not_run`），不得宣称视觉匹配。PDF 输入另受 PyMuPDF 许可与部署条件约束，不自动安装或转换。

## 美化已有 PPTX

若要求“保留措辞、页数、顺序，只改善版式”，遵循上游 Beautify 的 1:1 不变量：完整核对原文和数据，重新规划视觉，再新建 SVG/PPTX。明确 Quick 时才缩短策略环节。analyze 的内容输出仍须核对实际覆盖，不能仅凭摘要证明原文覆盖，必须读取实际 authoring/原稿内容并逐项校对。若目标是保留已有原生结构，只修改选定对象，走下方原生编辑而不是重生成。客户端渲染效果留待用户本地 PowerPoint/WPS 核对。

## 四类可复用模板

| 类型 | 保留的意图与边界 |
| --- | --- |
| Brand | 品牌身份、颜色、字体和获准的标识资源；不自动决定页序、内容或 Master/Layout |
| Style | 论证/证据习惯、视觉节奏、信息密度与表达规则；不固化来源的受众、页数、内容或画布 |
| Layout | 显式 Master/Layout/占位槽与几何契约，不把普通重复形状自动升级为布局 |
| Deck | 可复用页面角色/页组与组合范例；不是直接修改参考 PPTX 原件 |

按用途创建独立、可移植的模板工作区，保留来源事实与推断的区分、素材许可和依赖闭包。Brand/Style 单独使用保持 flat；Layout/Deck 拥有结构时才按完整显式元数据构建 structured。上游允许四类组合，每类最多一个明确工作区，Layout 对结构优先于 Deck；不能据此在未验证/未开放的 TL 入口强行执行。

template-import 提取参考材料，template-create/register/apply/preview 分别验证独立发行完整性与输入。可以整理需求与合法素材、说明缺口；不能调用内部 apply_template 绕过，不把支持目标写成已完成服务。

## 原生编辑与往返

已有 PPTX 的填充、选定文字/对象调整、原页重排/重复或只改备注/运动，采用 import→明确编辑清单→rebuild。使用源包生成的 authoring 名称及原生身份，未涉及内容保持原状，页序由 page_plan 声明。上游会按支持范围恢复未改页并补丁/重建已改对象，不承诺任意 Office 特性或整个 ZIP 的字节无损。对不支持对象、遗漏、退化和诊断必须保留，不能把空白或对象计数冒充完整读取。

## 动画与普通演讲者备注

build/rebuild 在支持的上游契约内处理普通文本备注、无声转场和动画配置。先验证 slide/group ID 与时间参数，再核对结构及客户端播放；动画 XML 存在不等于播放已验收。普通备注的生成、读取和往返保留，不改为音轨。

旁白合成、音频处理、字幕对齐和视频导出不再提供；不调用 TTS 服务、FFmpeg、PowerPoint 视频导出或下载模型。包含旧媒体配置的请求须明确报告不支持，不能当作无声普通演示继续处理。既有原稿内嵌内容的保留范围仍以实际往返回执为准，不承诺任意媒体无损。
