# BIFF8 共享与数组公式：仅保存值

维护资源说明：文中 `docs/maintenance/et/` 与 `skills/et/scripts/test/` 均以宿主确认的仓库根目录为基准，仅供源码维护，不随运行包分发；运行任务不读取或执行。没有仓库时跳过维护资料，不按 Skill 安装目录拼接。

路径占位符说明：`<skill-root>` 是 ET Skill 根目录的文档占位符，不是实际目录或 Shell 变量。取得宿主本次实际读取 ET 主入口 `SKILL.md` 的真实 `file_path`，若为相对路径，先按该次读取时宿主已确认的基准目录解析为绝对路径，再去掉末尾文件名；所得目录才是 `<skill-root>`，不是当前参考文档所在目录。读取资源或执行命令前，将路径中的 `<skill-root>` 整体替换为该真实目录，保留其后的资源路径；命令中将替换后的完整路径作为一个参数正确引用，嵌入 execute 字符串时按其语法转义。不要将占位符原样交给文件工具或执行器，不按当前工作目录、其他会话路径、环境变量或宿主掩码猜测。无法取得主入口的真实读取路径时，停止依赖操作并报告无法定位。

本读取范围依据 MS-XLS 的 ShrFmla、Array、PtgExp 与 FORMULA 顺序。这不是表达式或计算引擎。

每个成员仍从自己的 Formula/String 记录读取数字、文本、布尔、错误或空字符串缓存，标记未验证、可能过时。共享表达式不会复制为每个单元格公式；数组结果不会由锚点广播。只支持成员 tokens 为精确的单个 PtgExp（5 字节、无附加数据，规范要求忽略的保留高位不参与种类判断），不支持 Table 数据表公式或更复杂指针结构。

工作表 `formula_groups` 保留种类、锚点、零基范围、定义记录偏移、期望/实际成员数、原始 token/附加字节和头字段，并记录 `use_count_unspecified=true` 以区分声明 cUse=0 的异常生产者变体。单元格 `formula.group_anchor/group_kind` 仅表示对组定义的引用，**不是表达式中的依赖图**。组表达式与附加字节仅按外层长度切分，内部 token 语义未验证，因此有组定义的结果总是 partial，诊断 `formula_group_expression_not_decoded`。没有执行或恢复公式文本。

检查锚点自引用、定义紧随 Formula、fShrFmla 与组种类一致、成员坐标落在范围内、唯一地址及共享 cUse 成员数量；数组要求左上角锚点及范围内每个位置都有指向该组的 Formula。共享 cUse=0 在真实 WPS 原件中被观察到：仅当其余结构（范围、锚点、token 长度、重叠和成员标志）全部通过时，保留组定义并标 `use_count_unspecified`，用范围与共享标志关联成员，成员数不按 0 强制核对，并附 `formula_group_use_count_unspecified`；不把 0 解释为正常声明，也不取消其他校验。共享范围允许非成员空隙。重复锚点、缺失成员/锚点、截断长度及矛盾标志拒绝；重叠组边界作为当前不支持的结构明确拒绝（共享边界有空隙，因此拒绝不表示所有此类文件都损坏）。组定义/成员一致性属于元数据问题：定义损坏只保留 raw 与 issue，组锚点和成员的保存 Formula 缓存照常读取，不因此设置值遗漏或把 `cell_value_coverage` 降为不确定；若同一值承载记录或缓存本身缺失，才按值覆盖规则处理。

String 缓存允许出现在 Formula 和可选 ShrFmla/Array 之后，再接 Continue。缺失 String 缓存保留单元格并标 `cache_status=missing` 和 partial 诊断，不填零或空字符串。数组缺成员属于损坏，不把它解释为空缓存。

预算在保留组元数据前执行：每表最多 1024 个组，每组范围面积不超过既有 MAX_CELLS；共享 cUse 为 1–255 且不超过范围面积，或为 0 时仅按上述未指定变体保留；组原始数据计入已有元数据总预算。只遍历实际成员，不按范围分配矩阵。组冲突比较受 1024 上限约束。既有单元格、记录、诊断、输出配额继续适用。

新增覆盖是标准库合成规范样本，包含共享/数组不同缓存、定义与 String 顺序、成员缺失和冲突、边界、配额和显式拒绝。本轮 Edge 公开 ET 扩样在宁夏资金分配表中发现并保留两条 cUse=0 的 ShrFmla；其 79 个保存公式缓存由独立 oracle 核对一致。此前四份固定 ET/ETT 未提供此类共享公式独立语义对照；不能据单组真实变体声称所有 WPS 共享公式已通过验收。
