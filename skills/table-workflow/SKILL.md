## 最短任务路径

1. **识别**：读取本轮附件并根据用户要求判断来源/目标；只向 `inspect` 提交文件列表，stdout 是有界结构摘要。默认每表前 4 行、8 列，每文件最多 8 表；超过 8 表时先用 `names` 命令发现名称（单文件 stdin：`{"path":"./来源.xlsx","limit":32}`）；名称发现仍完整校验输入，但不先跨进程传输整表单元格；按返回 `next_offset` 以 `offset` 和同一 `sha256` 续读，直到 null。再用同一入口的 `sheet`/`range` 定位更下方表头，不逐页搬运全量数据。用打印的 SHA-256 绑定计划。

```python
execute(command="python -I -S -B \"<skill-root>/scripts/table_workflow.py\" inspect --xlsx-root \"XLSX_ROOT_CONFIRMED\" <<'JSON'\n{\"files\":[{\"path\":\"./当期.xlsx\"},{\"path\":\"./上期.xlsx\"},{\"path\":\"./目标.xlsx\"}]}\nJSON\n")
```

stdin 示例：`{"files":[{"path":"./当期.xlsx"},{"path":"./上期.xlsx"},{"path":"./目标.xlsx"}]}`。预览截断有明确数量；这是结构视图，不能拿来统计或作为完整源 JSON。超出 stdout 24000 字符时缩减预览并保留截断说明；必要时只返回核心状态和文件身份，再检查单文件/单表。任一 ET 来源为 partial 时，inspect 同样返回 partial/退出3，不能当成完整读取成功。

2. **映射**：仅此时读取 `<skill-root>/references/plan-contract.md`。从目标行键与列路径反向确定来源范围、关联键、过滤、明细/小计排除、单位、期间和计算口径；复杂表头使用明确的多级路径，不凭同名叶表头猜测。需要维表补列、业务勾稽或显式空值/缺期/零分母政策时，再读 `<skill-root>/references/quality-and-lookups.md`；普通汇总不加载该分支。已明确的映射直接执行；歧义只问相关项，不将每次填报变成审批流程。日期序列不推断；期间字段是声明，必须用真实范围或过滤落实。
3. **试算**：同一计划 JSON 经 stdin 交给 `plan`；在内存完整计算，检查匹配与模板公式，不生成中间文件。stdout 仅前 10 项写入、告警和计数；实际计算使用完整声明区域。
4. **填报**：试算通过且业务口径明确，执行同一计划的 `apply --output 填报.xlsx --audit 填报核验.json`。首次写入再核对依赖 XLSX 的编辑、公式及交付边界；本脚本通过稳定CLI保存已验证候选，统一调用 XLSX 交付能力，不再外包 runner 重算或重复生命周期登记。
5. **交付**：回读 ZIP 部件和原件指纹核对成功后，交付副本与审计 JSON。审计包含完整计划、来源 SHA、工作表/范围、物理行成员、分组勾稽、派生依赖、每格结果与舍入、保留内容验证；不是视觉或业务语义认证。stdout 是摘要，审计才是完整溯源。核验归档、清理与业务状态分别报告。

## 始终适用的边界

- 来源限受支持 XLSX/XLSM 和 ET/ETT。支持先做 one_to_one/many_to_one 维表补列，再按键聚合并匹配唯一目标键。维表必须唯一、类型一致；未匹配、空关联键、行数超限拒绝，核对事实行和值守恒。维表补入列只作属性，不作为金额聚合；不做多对多、模糊匹配或自动补目标行。简单创建 XLSX、单表 ET 读取仍使用原技能。
- 来源重复键必须显式选择 aggregate；缺失键、目标重复键、非数字金额和未知字段拒绝。未匹配目标、空数值组默认拒绝，明确 blank 才返回空值并保持 partial，不默认为零。隐藏/过滤行默认纳入；合计、重复表头及非明细行用原始行号明确排除，不自动识别。空数值默认拒绝；omit 忽略空值，blank 将含空值组留空，均为 partial。需要将空结果写入模板时，仅允许无公式模板，防止把缺失当零重算。
- 公式来源默认拒绝；明确采用缓存才用 cached，结果保留未验证警告并为 partial；缺失/错误缓存不使用。原生 XLSX 可 calculate；重算使用独立内存副本，不改变同文件其他区域的原保存缓存，声明顺序不影响结果。ET 不重算。源 partial 默认阻断；仅在契约允许的单元格覆盖或白名单样式元数据缺口得到明确接受后继续，输出仍 partial。未知遗漏和缺失公式缓存不能靠 accept_partial 放行。
- 目标仅已有 XLSX 副本。默认只写空白非公式单元格；replace_values 必须符合用户授权的目标范围。写前逐格比对实际候选与计算清单，拒绝新增非目标单元格或包部件；保护原件、键、表头、现有样式、非目标值和公式文本；不承诺整个文件字节一致。所有公式先在候选内重算，任何不支持/错误/循环、特殊公式或未刷新图表/透视/外链缓存均拒绝发布；不能静默清除缓存交付。不是任意无损编辑或 ET 写回。
- 勾稽在未舍入指标上执行，明确逐目标键/目标总计/全部来源组总计、单位、期间和容差；失败或无法核验默认阻断。明确 partial 才继续，完整检查记录进入审计。缺期仅按显式 YYYY-MM 字段和预期月份逐实体检查，不推断日期序列或用上一行代替缺期。ratio 专用操作可明确零分母留空；通用公式不吞掉计算错误。
- 单位变更需要明确倍率；目标单位和期间必须与指标一致。派生公式的经济含义和量纲仍由模型/用户审核；脚本只按显式绑定计算，不理解业务。不使用 eval 或执行输入代码。金额最终按指定小数位 ROUND_HALF_UP，超出支持的 Excel 数值精度拒绝。
- 所有任务参数经 stdin，无需临时计划/脚本。只有 final XLSX 与审计 JSON 落盘；独占写入，已有文件不覆盖。审计内 plan 保留 JSON 数字/文本类型与十进制精度，可经同一请求入口重放。若宿主必须另存辅助文件，先读取公共 artifact-lifecycle 真实入口并创建前登记；找不到公共包就报告，不猜路径。失败待重试保留诊断及已产生最终文件，不认领/删除历史文件。
- 归档经稳定 CLI 复用 XLSX 内置实现；核对 delivery 中 XLSX 与核验 JSON 两项实际结果，两项均成功才提示“🎉 文件归档成功，请到云空间查看。 ☁️✨”；仅一项成功提示“部分文件归档成功，请到云空间查看已归档文件；其余文件归档未完成。”并说明另一项状态。两项均未成功按实际失败、跳过或未知报告；压缩回执保留每项 archive_user_notice，机器 archive_message 不变。归档失败保留主文件、不重跑。失败、部分成功、跳过、待交接和未知分别如实报告，不套用全部成功；业务与清理状态独立，主业务失败不称生成成功。隐藏归档路径、目录、ID及原始日志，保留真实主文件链接，不虚构下载。
- 退出 0 表示本次命令完成；退出 3 保留 partial 或交付收尾不完整，先检查完整 JSON；退出 1 为失败，退出 2 为参数错误。成功读取不证明格式完全兼容；不能把失败、截断或部分结果当作完整成功。失败时核对 output_written、audit_written 和 verification；incomplete/unknown 不可当作文件完整成功。投影裁剪保留已生成文件、partial 与收尾状态，不因长日志改写业务结果。
